# tgmcp

MCP-сервер, через который Claude ищет информацию в **заданном списке Telegram-чатов**: находит вопросы людей, обсуждения и ответы. Сервер работает как гид по направлениям, которые покрывают эти чаты: при старте он изучает каждый чат и отдаёт Claude описание того, о чём там говорят, чтобы на вопрос пользователя выбирались подходящие чаты. Работает от имени юзербота (обычного аккаунта Telegram) и **только читает**: инструментов для отправки, редактирования или вступления в чаты нет, а запрос к любому чату вне списка `TG_CHATS` отклоняется.

Поддерживаются два режима:
- **HTTP (основной)** — сервер работает на удалённой машине в Docker и подключается к claude.ai как *custom connector*, а также к Claude Code и Claude Desktop;
- **stdio** — Claude Code или Claude Desktop запускают сервер локально.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `list_chats` | Полные профили чатов: описание, закреп, топики форума, активность, частые слова, недавние вопросы |
| `search_messages` | Поиск по ключевым словам сразу по нескольким вариантам запроса (синонимы, языки, основы слов) с фильтрами по дате, автору, топику и типу (ссылки, документы, закреплённые и т.д.) |
| `search_discussions` | Поиск, после которого каждая находка разворачивается в целое обсуждение: исходный вопрос, ответы через reply и сообщения, написанные после него без reply. Если находка — ответ без reply, показываются и сообщения перед ней |
| `find_questions` | Вопросы людей по теме или просто за период вместе с ответами: и через reply, и написанными следом; можно выбрать только неотвеченные |
| `get_thread` | Весь разговор вокруг сообщения: цепочка вверх до корня, все ответы и сообщения, написанные после корня без reply; для поста канала — комментарии |
| `get_message_context` | Сообщения до и после указанного в хронологическом порядке (в форуме — в пределах топика) |
| `get_chat_history` | Последние сообщения, диапазон дат, один топик или один автор, с постраничной загрузкой |
| `get_messages` | Конкретные сообщения по id |
| `list_topics` | Топики форумов, можно с фильтром по названию |

Каждое сообщение возвращается со ссылкой `t.me/...`, чтобы Claude мог сослаться на источник.

### Как сервер понимает, о чём чаты

Тематики в конфиге задавать не нужно: при старте сервер один раз собирает профиль каждого чата из `TG_CHATS`:
- описание чата и закреплённые сообщения;
- список топиков, если чат — форум;
- выборка последних сообщений (`TG_PROFILE_SAMPLE`, по умолчанию 300): из неё берутся частые слова, недавние вопросы участников и активность чата.

Краткий каталог чатов попадает в инструкции сервера, которые Claude получает при подключении, а полный профиль отдаёт `list_chats`. Сопоставляет вопрос с чатами сам Claude: он выбирает подходящие чаты (один чат может подходить под разные темы) и ищет только в них. Если вопрос не подходит ни к одному чату, Claude так и говорит и перечисляет, о чём чаты есть, а по всем чатам ищет только по явной просьбе.

Что сервер «понял» про чаты, видно в `tgmcp --check`. Если профиль вышел неудачным (например, у чата пустое описание и мало сообщений), увеличьте `TG_PROFILE_SAMPLE`.

### Ответы без reply

Многие отвечают, не нажимая «ответить», а просто пишут следом. Поэтому обсуждение собирается из трёх частей:
- **ответы через reply** — помечены `(reply)`;
- **сообщения, написанные после вопроса без reply** — помечены `(after)`. По умолчанию берутся до 10 следующих сообщений за 24 часа, в форуме — только в том же топике. Сообщения, которые являются reply на что-то постороннее, отбрасываются: это другие разговоры. Ответы на `(after)`-сообщения включаются;
- **сообщения перед находкой**, если сама находка не вопрос и не reply, то есть, скорее всего, ответ без reply на что-то выше.

Всё выводится одной хронологической лентой. Глубину и окно Claude регулирует параметрами `follow_ups` и `follow_window_hours`. В активных чатах среди `(after)` попадается посторонняя болтовня — Claude предупреждён, что её нужно отсеивать по смыслу.

## Быстрый старт (Docker Compose, удалённый сервер)

**1. Данные API.** На https://my.telegram.org → *API development tools* получите `api_id` и `api_hash`.

> Для юзербота лучше завести отдельный аккаунт и добавить его в нужные чаты. Строка сессии даёт **полный доступ** к аккаунту — храните `.env` как пароль.

**2. Конфиг.**
```bash
git clone <repo> tgmcp && cd tgmcp
cp .env.example .env
# заполните TG_API_ID, TG_API_HASH, TG_CHATS и MCP_AUTH_TOKEN:
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'
```

**3. Вход в Telegram** (один раз, интерактивно: телефон, код, пароль 2FA):
```bash
docker compose build
docker compose run --rm tgmcp tgmcp-login
# скопируйте строку TG_SESSION=... в .env
```

**4. Проверка** — сессия валидна и все чаты найдены:
```bash
docker compose run --rm tgmcp tgmcp --check
```

**5. Запуск с HTTPS.** Укажите в `.env` `DOMAIN=mcp.example.com` (A-запись домена должна указывать на сервер, порты 80 и 443 открыты), затем:
```bash
docker compose --profile https up -d
curl https://mcp.example.com/health
```
Встроенный Caddy сам получит сертификат Let's Encrypt. Если у вас уже есть свой reverse proxy (nginx, Traefik), запускайте без профиля (`docker compose up -d`) и проксируйте на `127.0.0.1:8000`. Для `/mcp` поставьте таймаут чтения не меньше нескольких минут.

## Подключение к Claude

### claude.ai (custom connector)
*Settings → Connectors → Add custom connector*, URL:
```
https://mcp.example.com/<MCP_AUTH_TOKEN>/mcp
```
Токен передаётся в пути, потому что коннектор принимает только URL. Не публикуйте эту ссылку: она и есть пароль. Чтобы отозвать доступ, смените `MCP_AUTH_TOKEN` и выполните `docker compose up -d`.

### Claude Code — удалённый сервер
```bash
claude mcp add --transport http telegram https://mcp.example.com/mcp \
  --header "Authorization: Bearer <MCP_AUTH_TOKEN>"
```

### Claude Code / Claude Desktop — локально (stdio)
```bash
python3 -m venv .venv && .venv/bin/pip install .
.venv/bin/tgmcp-login            # затем заполните .env
claude mcp add telegram -- /abs/path/tgmcp/.venv/bin/tgmcp --transport stdio --env-file /abs/path/tgmcp/.env
```
Claude Desktop (`claude_desktop_config.json`):
```json
{
  "mcpServers": {
    "telegram": {
      "command": "/abs/path/tgmcp/.venv/bin/tgmcp",
      "args": ["--transport", "stdio", "--env-file", "/abs/path/tgmcp/.env"]
    }
  }
}
```
> Не запускайте одну и ту же `TG_SESSION` одновременно в двух местах, например в Docker на сервере и локально через stdio: Telegram может отозвать ключ сессии (`AUTH_KEY_DUPLICATED`). Для второго места создайте отдельную сессию через `tgmcp-login`.

## Юзербот, который уже используется другим сервисом

Один аккаунт может одновременно иметь много сессий, как телефон, десктоп и веб у обычного пользователя. Поэтому MCP-сервер можно запустить на аккаунте, который уже обслуживает другой сервис, в том числе на том же сервере. Условие одно: **у MCP-сервера должна быть своя сессия.**

- **Нельзя** копировать в `TG_SESSION` строку сессии или `.session`-файл работающего сервиса. Если два процесса одновременно работают с одним ключом авторизации, Telegram может отозвать его (`AUTH_KEY_DUPLICATED`). Тогда отвалятся оба сервиса.
- **Нужно** выполнить `tgmcp-login` тем же номером. Код придёт в Telegram; `api_id`/`api_hash` можно взять те же. В «Активных сеансах» появится отдельное устройство `tgmcp`. Первый сервис это не затронет, а MCP-сервер можно отключить, завершив только его сеанс.

Что учесть:
- **Лимиты Telegram (FloodWait) общие на аккаунт.** Если первый сервис критичен, снизьте `TG_PARALLEL_REQUESTS` (например, до 2) и при необходимости увеличьте `TG_CACHE_TTL`.
- **Аккаунт должен состоять во всех чатах из `TG_CHATS`.**
- **Содержимое этих чатов будет попадать в Claude от имени этого аккаунта.**

## Список чатов (`TG_CHATS`)

Через запятую, точку с запятой или с новой строки:
- `@username`, `username`, `https://t.me/username`
- `-1001234567890` или `https://t.me/c/1234567890/...` — для приватных чатов, где аккаунт уже состоит
- `https://t.me/+InviteHash` — приватный чат по инвайту; аккаунт должен уже быть участником, сервер сам никуда не вступает

Чаты, которые не удалось найти, пропускаются с предупреждением в логе и видны в `list_chats`/`--check`.

## Нагрузка: много клиентов одновременно

Все клиенты работают через **одну** Telegram-сессию в **одном** асинхронном процессе. Несколько процессов на одну сессию запускать нельзя (см. выше). Поэтому сервер не масштабируется воркерами, а держит нагрузку так:

- **Очередь вызовов.** Одновременно выполняется не больше `MCP_MAX_CONCURRENT_CALLS` инструментов, остальные ждут в FIFO-очереди. Если ожидание дольше `MCP_QUEUE_TIMEOUT` или очередь длиннее `MCP_MAX_QUEUE`, клиент получает ошибку «server busy, retry shortly». Процесс при этом не падает.
- **Лимит запросов к Telegram** (`TG_PARALLEL_REQUESTS`). FloodWait до 60 с сервер переживает автоматически: запрос просто ждёт.
- **Общий кэш** (`TG_CACHE_TTL`). Одинаковые чтения от разных клиентов в пределах TTL уходят в Telegram один раз; одновременные одинаковые запросы объединяются в один.
- **Ограничение соединений** (`MCP_MAX_CONNECTIONS`). Сверх лимита uvicorn отвечает 503, а не перегружается.
- **HTTP-режим без хранения сессий**: перезапуск сервера не ломает подключённых клиентов.
- **Watchdog.** Если Telegram недоступен и переподключиться не удаётся, процесс завершается, и Docker (`restart: unless-stopped`) поднимает его заново.

Текущее состояние видно в `GET /health`: число выполняющихся и ожидающих вызовов, попадания в кэш.

## Заполнение .env

Скопируйте шаблон: `cp .env.example .env`. Пишите значения без кавычек и без пробелов вокруг `=`. Файл `.env` секретный: его нельзя коммитить и пересылать.

### Обязательные

| Переменная | Что указать | Где взять |
|---|---|---|
| `TG_API_ID` | Число, например `1234567` | https://my.telegram.org → войти номером аккаунта → *API development tools* → создать приложение (название любое). Можно взять ключи вашего другого сервиса |
| `TG_API_HASH` | 32 символа, например `0123456789abcdef0123456789abcdef` | Там же |
| `TG_SESSION` | Длинная строка, начинается с `1` | Сначала заполните `TG_API_ID` и `TG_API_HASH`, затем `docker compose run --rm tgmcp tgmcp-login`: номер, код из Telegram, пароль 2FA. Скопируйте выведенную строку `TG_SESSION=...`. **Не берите сессию другого работающего сервиса** (см. раздел про юзербот выше) |
| `TG_CHATS` | Чаты одной строкой через запятую | См. ниже |
| `MCP_AUTH_TOKEN` | Случайная строка, минимум 16 символов | `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`. Нужен в HTTP-режиме, то есть всегда в Docker |
| `DOMAIN` | Домен сервера, например `mcp.example.com` | Нужен только для встроенного HTTPS (`--profile https`). A-запись домена должна указывать на сервер, а порты 80 и 443 должны быть открыты |

**Как указать чат в `TG_CHATS`:**
- **Публичный чат или канал:** `@username` или `https://t.me/username`.
- **Приватный чат:** проще всего вставить ссылку на любое его сообщение (*правый клик → Copy Message Link*). Получится вида `https://t.me/c/1234567890/55`, номер сообщения роли не играет. Подойдёт и числовой id `-1001234567890`: его видно в адресной строке web.telegram.org, когда чат открыт.
- **Инвайт-ссылка** `https://t.me/+AbCdEf`: сервер сам никуда не вступает, поэтому аккаунт уже должен состоять в чате.

Пример: `TG_CHATS=@python_ru, https://t.me/c/1234567890/55, -1009876543210`

Пишите список одной строкой: многострочные значения Docker Compose читает ненадёжно. Проверить, что все чаты найдены, можно командой `docker compose run --rm tgmcp tgmcp --check`.

### Необязательные

| Переменная | По умолчанию | Когда менять |
|---|---|---|
| `TG_PROXY` | пусто | Если Telegram на сервере заблокирован: `socks5://user:pass@host:1080` или `http://host:3128` |
| `TG_MAX_MESSAGE_CHARS` | `1500` | Сколько символов одного сообщения отдавать Claude; `0` — без обрезки |
| `TG_PROFILE_SAMPLE` | `300` | Сколько последних сообщений читать из каждого чата при старте, чтобы понять его тематику; `0` — не читать |
| `TG_PARALLEL_REQUESTS` | `4` | Сколько запросов к Telegram идёт одновременно. Если на этом аккаунте работает другой сервис, поставьте `2` |
| `TG_CACHE_TTL` | `120` | Сколько секунд переиспользовать одинаковые запросы; `0` — без кэша |
| `MCP_MAX_CONCURRENT_CALLS` | `8` | Сколько вызовов инструментов выполняется одновременно, остальные ждут в очереди |
| `MCP_QUEUE_TIMEOUT` | `120` | Сколько секунд вызов может ждать в очереди, прежде чем клиент получит «server busy» |
| `MCP_MAX_QUEUE` | `200` | Максимальная длина очереди |
| `MCP_MAX_CONNECTIONS` | `256` | Сколько HTTP-соединений обслуживается одновременно; сверх лимита сервер отвечает 503 |
| `TGMCP_LOCAL_PORT` | `8000` | Порт на `127.0.0.1` хоста, если 8000 занят. Нужен, когда вы проксируете своим nginx или Traefik |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING` или `ERROR` |
| `MCP_TRANSPORT`, `MCP_HOST`, `MCP_PORT` | `http`, `0.0.0.0`, `8000` | Только для запуска без Docker: в Docker их задаёт `docker-compose.yml`, и значения из `.env` игнорируются. Для локального stdio-режима поставьте `MCP_TRANSPORT=stdio` |
| `MCP_ALLOW_NO_AUTH` | пусто | `true` разрешает HTTP без токена. Не рекомендуется: любой, кто достучится до порта, сможет читать ваши чаты |

### Минимальный пример

```env
TG_API_ID=1234567
TG_API_HASH=0123456789abcdef0123456789abcdef
TG_SESSION=1BVtsOK8Bu...очень длинная строка...
TG_CHATS=@python_ru, https://t.me/c/1234567890/55
MCP_AUTH_TOKEN=Zq3v9mJ0yX2b...
DOMAIN=mcp.example.com
```

После изменения `.env` перезапустите контейнер: `docker compose --profile https up -d`.

## Ограничения

- Поиск Telegram работает по ключевым словам: семантики нет, морфология слабая. Сервер подсказывает Claude передавать несколько вариантов запроса: синонимы, основы слов, оба языка.
- В обычных (не супер-) группах нет нативных тредов, поэтому ответы собираются сканированием сообщений после вопроса (до 2000 штук).
- Связь «вопрос → ответ без reply» эвристическая: это сообщения, написанные следом. Поэтому `unanswered_only` консервативен: в активном чате вопрос, после которого кто-то что-то написал, считается возможно отвеченным.

## Разработка

```bash
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/pytest
```
Тесты используют фейковый Telegram-клиент и поднимают настоящий HTTP-сервер: проверяются авторизация, 20 параллельных клиентов через очередь, кэш, треды и форумы.
